Superseded one-pair result

observed baseline 69,828,608 B and uncompacted registry 88,473,600 B, a
26.701079 percent increase, and correctly recorded that observation as blocked.

supersession.

    #[cfg(feature = "allocation-measurement")]
    #[test]
    fn diagnostic_registry_peak_for_100_000_identities() {
        const IDENTITY_COUNT: u64 = 100_000;
        const PEAK_BYTES_LIMIT: usize = 29_457_573;

        let profiler = dhat::Profiler::builder().testing().build();
        let mut registry = ScopeRegistry::new();
        let root = registry.root();
        let node = ScopeNodeId(1);
        for identity in 0..IDENTITY_COUNT {
            std::hint::black_box(registry.mount(root, node, ScopeIdentity::new(identity)));
        }
        let mounted = dhat::HeapStats::get();
        drop(registry);
        let finished = dhat::HeapStats::get();

        eprintln!(
            "registry_dhat mounted_live_blocks={} mounted_live_bytes={} total_blocks={} total_bytes={} final_live_blocks={} final_live_bytes={} peak_blocks={} peak_bytes={}",
            mounted.curr_blocks,
            mounted.curr_bytes,
            finished.total_blocks,
            finished.total_bytes,
            finished.curr_blocks,
            finished.curr_bytes,
            finished.max_blocks,
            finished.max_bytes
        );
        assert!(finished.max_bytes <= PEAK_BYTES_LIMIT);
        drop(profiler);
    }
    // TASK4_DHAT_DIAGNOSTIC_END

DHAT's `t-gmax` block field is the number of live blocks at the maximum-byte
instant, not an independent maximum block count. This is why repaired `t-gmax`
reports 57,349 live blocks while the later fully mounted sample contains
100,004. DHAT observes allocator heap inside one local test process; it does not
measure RSS, operating-system allocations, or allocator fragmentation outside
its accounting.

Attribution and arithmetic
==========================

Independent `awk` calculations from raw values produced:
  100,000 initial-mount speed-up = 3125 ms / 35.49 ms = 88.052973x
  100,000 bulk-row speed-up = 163.5 ms / 4.379 ms = 37.337292x
  repaired initial scale = 35,490 us / 348 us = 101.982759x
  repaired bulk row ratio = 4.379 ms / 0.2397 ms = 18.268669x
  RSS ratio = 48,422,912 / 64,446,464 = 0.751366468
  RSS change = -16,023,552 * 100 / 64,446,464 = -24.863353 percent
  DHAT peak change = -2,072,140 * 100 / 26,779,612 = -7.737752 percent

Initial mounting n distinct identities is average O(n): each indexed lookup is
average O(1) plus its selected collision chain, and the measured 100x input
increase grew 101.98x. Registry invalidation of M siblings is average O(M)
because unlink and traversal are average O(1) per invalidated node. The bulk
benchmark still includes the keyed collection's O(n) before/after scans, so its
two rows support the registry attribution but are not an isolated complexity
proof. Collision lookup is O(c) for collision-chain length c, with concrete
identity equality retained as authority. Matching, unrelated, and other
unchanged keyed reconciliations remain O(n) until Task 6 adds the separately
proved structural-stamp fast path.
